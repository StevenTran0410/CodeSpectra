* **Category Breakdown**:

    * `gibberish`: 25 cases (verdict: reject)

    * `policy_evasion`: 30 cases (verdict: reject)
    * `borderline_valid`: 30 cases (verdict: pass)

  * Mechanical categories generated via deterministic templates + light paraphrasing (no LLM).
  * Semantic categories generated via adversarial LLM prompting using specific category rubrics.

* **Known Gaps/Limitations**: The semantic cases generated by the LLM are synthetic approximations and may contain subtle phrasing ambiguities. Human review is strictly required to verify ground truth labels before grading down-stream runs.

## 2. QA Testset Engine: RAGAS vs. DeepEval Comparison

An empirical evaluation was conducted comparing the two candidate libraries for generating RAG testsets on the T1 corpus:

| Criteria | RAGAS (`TestsetGenerator`) | DeepEval (`Synthesizer`) |
| :--- | :--- | :--- |
| **Setup Friction** | **Extremely High**: Requires custom Langchain LLM wrapper and a custom Langchain Embedding wrapper. Throws `ModuleNotFoundError` if external dependency `rapidfuzz` is missing during NER extraction. Fails with `ValueError` if document length is <= 100 tokens, requiring manual padding. | **High**: Requires custom LLM and Embedding adapters. Calls to evaluate chunk/context quality utilizing structured Pydantic schemas raise `TypeError` if custom model's `generate` does not support `schema`, requiring robust mock/routing. |
| **Execution Complexity** | **Very High**: Builds a complex knowledge graph and generates personas, matching them to themes/concepts via multiple extraction prompts before scenario/sample generation. | **High**: Constructs contexts by chunking and filters/rewrites them using a Critic model filtration loop before styling and evolving. |
| **Parsing & Formatting** | Returns `user_input`, `reference`, and `reference_contexts` columns. Ragas output parsers automatically retry using a fix prompt if LLM responses do not match the expected Pydantic schema formats. | Returns standard `input` and `expected_output` fields. DeepEval relies on schema-based generation fallback in `trimAndLoadJson` if a custom model does not support schema arguments. |
| **License / Deps** | Apache 2.0. High dependency weight (installs Langchain ecosystem, numpy, rapidfuzz). | Apache 2.0. Clean, modular CLI-first design but has medium-heavy dependencies (chromadb, Confident AI telemetry). |

**Recommendation**: **DeepEval** is selected as the default backend. It generates structured synthetic goldens with slightly less setup overhead than Ragas, which has heavy restrictions on minimum document size and extra external dependencies (like `rapidfuzz`). Ragas is maintained as a robust alternate backend behind the `QATestsetBackend` protocol.
